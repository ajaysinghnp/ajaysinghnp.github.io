# AI Agent Guardrails

## Overview

This document defines the security and safety guardrails that AI agents must follow when working with this codebase. These guardrails ensure responsible AI usage and protect the project from potential security risks.

## Core Principles

### 1. Environment Access

**NEVER read or access sensitive environment files:**

- `.env` files (containing API keys, tokens, secrets)
- `.env.local`, `.env.development.local`, `.env.test.local`, `.env.production.local`
- Any file containing authentication credentials

**ALLOWED:**

- Reading `.env.example` files for documentation purposes
- Accessing public configuration files
- Reading environment variables explicitly documented in project configuration

### 2. Code Execution

**NEVER execute code without explicit user permissions:**

- Never run scripts that modify the file system
- Never execute code that accesses external services without permission
- Never run code that could expose sensitive data

**ALLOWED:**

- Running development servers (`pnpm dev`) with user confirmation
- Executing build scripts (`pnpm build`) with user confirmation
- Running tests (`pnpm test`) with user confirmation

### 3. Data Handling

**NEVER expose or mishandle sensitive data:**

- Never commit secrets to version control
- Never log sensitive data (API keys, passwords, tokens)
- Never expose user data or personal information
- Never share internal configuration details

**ALLOWED:**

- Working with anonymized or aggregated data
- Handling public repository information
- Processing non-sensitive user-generated content

### 4. File System Access

**NEVER access or modify protected files:**

- Never read `.env` files
- Never write to system directories
- Never modify version control files without permission
- Never delete or rename critical project files

**ALLOWED:**

- Reading and modifying source code files
- Creating new documentation files
- Modifying configuration files that are not security-sensitive

### 5. Network Access

**NEVER access unauthorized endpoints:**

- Never call external APIs without user permission
- Never access internal network resources
- Never bypass rate limits or authentication

**ALLOWED:**

- Making API calls to public GitHub endpoints (with proper rate limiting)
- Accessing public documentation and resources
- Using approved external services

## Testing & Quality Assurance

### Pre-Commit Requirements

**ALWAYS run before committing:**

1. `pnpm typecheck` - TypeScript type checking
2. `pnpm lint` - Code linting
3. `pnpm format` - Code formatting
4. `pnpm check` - Full quality check (typecheck + lint + format)

**NEVER commit if:**

- Any TypeScript errors exist
- Linting issues are present
- Formatting is not applied
- Tests are failing

### Pre-Push Requirements

**ALWAYS verify before pushing:**

1. All tests pass
2. Type safety is maintained
3. Code quality is confirmed
4. Formatting is validated

**NEVER push if:**

- Any tests fail
- Type safety is compromised
- Code quality standards are not met
- Repository is in an inconsistent state

## AI Agent Behavior Guidelines

### When Asking for Help

**DO:**

- Provide specific file paths and code snippets
- Ask for concrete examples of similar patterns
- Request clarification on design decisions
- Ask for specific implementation details

**DO NOT:**

- Ask for sensitive information (API keys, passwords, tokens)
- Request access to internal systems
- Ask for personal or private data
- Request code that bypasses security measures

### When Generating Code

**DO:**

- Follow existing patterns and conventions
- Use TypeScript for type safety
- Consider accessibility and performance
- Write clean, maintainable code
- Include proper error handling
- Add appropriate comments and documentation

**DO NOT:**

- Generate code that contains hardcoded secrets
- Create code that bypasses authentication
- Write code that exposes sensitive data
- Generate code with security vulnerabilities

## Troubleshooting

### Common Issues

**TypeScript Errors:**

- Run `pnpm typecheck` for detailed error messages
- Fix type annotations and interfaces
- Ensure proper type imports and exports

**Linting Issues:**

- Run `pnpm lint` to identify problems
- Follow ESLint rules and conventions
- Fix code style and formatting issues

**Build Failures:**

- Check console output for specific error messages
- Review build logs for detailed information
- Ensure all dependencies are properly installed

**Development Server Issues:**

- Try `pnpm dev --turbo` if available
- Check for port conflicts
- Verify environment configuration

### Getting Help

**Available Resources:**

- `README.md` - General project information
- `components/` - Component examples
- `app/api/` - API route examples
- `lib/` - Utility function examples
- `README-AI-AGENTS.md` - AI agent integration guide

**When seeking assistance:**

1. Provide specific error messages and code snippets
2. Include relevant file paths and context
3. Describe the problem clearly and concisely
4. Explain what you've already tried

## Emergency Procedures

### If Security Issues are Suspected

1. **Immediately stop** any AI agent interactions
2. **Document** what was accessed or attempted
3. **Report** to the project maintainer
4. **Secure** any potentially exposed credentials

### If Code Quality Issues Arise

1. **Run** the full quality check: `pnpm check`
2. **Review** all errors and warnings
3. **Fix** issues systematically
4. **Test** changes before committing
