# AI Agent Compliance Checklist

## Overview

This checklist ensures AI agents comply with industry standards and best practices when working with this codebase. It covers security, quality, and operational requirements.

## Security & Safety

### Environment Access

- [ ] NEVER read `.env` files (containing API keys, tokens, secrets)
- [ ] NEVER access `.env.local`, `.env.development.local`, `.env.test.local`, `.env.production.local`
- [ ] NEVER read any file containing authentication credentials
- [ ] ALWAYS read only `.env.example` for documentation purposes
- [ ] ALWAYS respect file system boundaries and permissions

### Code Execution

- [ ] NEVER run code without explicit user permissions
- [ ] NEVER execute scripts that modify the file system without confirmation
- [ ] NEVER run code that accesses external services without user approval
- [ ] NEVER execute code that could expose sensitive data
- [ ] ALWAYS get user confirmation before running development servers (`pnpm dev`)
- [ ] ALWAYS get user confirmation before running build scripts (`pnpm build`)
- [ ] ALWAYS get user confirmation before running tests (`pnpm test`)

### Data Handling

- [ ] NEVER expose or mishandle sensitive data
- [ ] NEVER commit secrets to version control
- [ ] NEVER log sensitive data (API keys, passwords, tokens)
- [ ] NEVER expose user data or personal information
- [ ] NEVER share internal configuration details
- [ ] ALWAYS work with anonymized or aggregated data when possible
- [ ] ALWAYS handle public repository information appropriately
- [ ] ALWAYS process non-sensitive user-generated content

### Network Access

- [ ] NEVER access unauthorized endpoints
- [ ] NEVER call external APIs without user permission
- [ ] NEVER access internal network resources
- [ ] NEVER bypass rate limits or authentication
- [ ] ALWAYS respect rate limits when accessing public APIs
- [ ] ALWAYS use proper authentication for authorized API access
- [ ] NEVER write to protected system paths or files
- [ ] ALWAYS validate and sanitize user inputs

## Code Quality & Testing

### Pre-Commit Requirements

**ALWAYS run before committing:**

- [ ] `pnpm typecheck` - TypeScript type checking
- [ ] `pnpm lint` - Code linting
- [ ] `pnpm format` - Code formatting
- [ ] `pnpm check` - Full quality check (typecheck + lint + format)

**NEVER commit if:**

- [ ] Any TypeScript errors exist
- [ ] Linting issues are present
- [ ] Formatting is not applied
- [ ] Tests are failing

### Pre-Push Requirements

**ALWAYS verify before pushing:**

- [ ] All tests pass
- [ ] Type safety is maintained
- [ ] Code quality is confirmed
- [ ] Formatting is validated

**NEVER push if:**

- [ ] Any tests fail
- [ ] Type safety is compromised
- [ ] Code quality standards are not met
- [ ] Repository is in an inconsistent state

## Emergency Procedures

### If Security Issues are Suspected

1. **Immediately stop** any AI agent interactions
2. **Document** what was accessed or attempted
3. **Report** to the project maintainer
4. **Secure** any potentially exposed credentials

### If Code Quality Issues Arise

1. **Run** the full quality check: `pnpm check`
2. **Review** all errors and warnings
3. **Fix** issues systematically
4. **Test** changes before committing
