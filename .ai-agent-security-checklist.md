# AI Agent Security Checklist

## Overview

This checklist provides comprehensive security guidelines for AI agents working with this Next.js project. It covers environment security, code security, data security, and operational security.

## Environment Security

### Environment Variable Management

**NEVER access or expose sensitive environment variables:**

- [ ] NEVER read `.env` files
- [ ] NEVER read `.env.local` files
- [ ] NEVER read `.env.development.local` files
- [ ] NEVER read `.env.test.local` files
- [ ] NEVER read `.env.production.local` files
- [ ] NEVER expose API keys, tokens, or secrets
- [ ] NEVER commit environment files to version control
- [ ] NEVER log environment variables
- [ ] NEVER share environment configurations

**ALLOWED:**

- [ ] Read `.env.example` for documentation purposes
- [ ] Access public configuration files
- [ ] Use environment variables explicitly documented in project configuration

### File System Security

**NEVER access protected files or directories:**

- [ ] NEVER read `.env` files
- [ ] NEVER read `.env.*` files
- [ ] NEVER access system directories
- [ ] NEVER modify protected configuration files
- [ ] NEVER write to system paths
- [ ] NEVER delete critical project files
- [ ] NEVER rename important files
- [ ] NEVER create files in protected directories

**ALLOWED:**

- [ ] Read and modify source code files
- [ ] Create new documentation files
- [ ] Modify non-sensitive configuration files
- [ ] Create files in project directories

## Code Security

- [ ] Validate all user inputs

## Emergency Procedures

### If Security Issues are Suspected

1. **Immediately stop** any AI agent interactions
2. **Document** what was accessed or attempted
3. **Report** to the project maintainer
4. **Secure** any potentially exposed credentials
5. **Investigate** the security issue
6. **Fix** the security issue
7. **Prevent** similar issues in the future

### If Code Quality Issues Arise

1. **Run** the full quality check: `pnpm check`
2. **Review** all errors and warnings
3. **Fix** issues systematically
4. **Test** changes before committing
5. **Document** the fixes
6. **Prevent** similar issues in the future
